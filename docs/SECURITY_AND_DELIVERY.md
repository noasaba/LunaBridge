# Security and delivery semantics

## Transport

The only operator-facing secret is `network.shared-pass`. LunaBridge normalizes it, requires 16 or more characters, and derives a backend-specific key internally. A Paper backend starts a bounded HMAC-SHA-256 hello/challenge/proof handshake. The transcript derives independent client→server and server→client AES-256-GCM keys and nonce prefixes through HKDF-SHA-256.

Every encrypted frame authenticates its header as additional data and binds protocol version, type ID, session ID, persisted Velocity epoch, sequence, issue/expiry times, and request ID. Frames are limited to 28 KiB plaintext and five minutes maximum lifetime; the normal bridge lifetime is ten seconds. A 64-sequence sliding replay window is checked only after GCM authentication. Authentication, session, protocol, expiry, replay, and capability failures invalidate the network session; there is no insecure fallback.

## Delivery contract

`ACCEPTED` means Velocity admitted the source request. `FORWARDED`/`REMOTE_ACCEPTED` are internal routing milestones. `DELIVERED` means a destination Paper adapter completed LunaChat dispatch; it never claims a client rendered the line. `FAILED`, `EXPIRED`, and `INDETERMINATE` remain failures.

Network channel chat is best effort at the Paper edge. LunaChat has already accepted and rendered its local message before the asynchronous bridge work is attempted. A missing carrier, Velocity restart, queue pressure, Discord outage, or ACK timeout therefore never cancels local chat or prints a generic transport failure to players. In contrast, a shared-pass mismatch or tampered frame fails closed for the bridge and is logged for operators.

## Bounds

| State | Bound / policy |
| --- | --- |
| Paper pre-session outbox | configurable 1–4,096 entries; max 16 KiB per message; 3 attempts; expiry deadline |
| Velocity pending delivery | one network-global configurable 1–4,096 entry cap; two exact-byte retries; 10-second deadline |
| Handshake challenges | 128 entries, 30-second expiry |
| Backend sessions | 512 entries |
| Message deduplication | configurable 64–100,000 entries, 24-hour TTL; full means reject/drop new work, never evict live records |
| Discord REST work | 256 in-flight requests; queue pressure drops relay/notification work rather than retaining it |
| First-login ledger | 50,000 UUIDs persisted to disk |

Discord user and Minecraft message content have all `@` characters neutralized for outgoing Discord relay. The only permitted role mention is the configured first-login role ID; it is generated by LunaBridge and is the only mention in that message.
