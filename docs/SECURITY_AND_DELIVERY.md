# Security and delivery semantics

## Transport

The only operator-facing secret is `network.shared-pass`. LunaBridge normalizes it, requires 16 or more characters, and derives a backend-specific key internally. A Paper backend starts a bounded HMAC-SHA-256 hello/challenge/proof handshake. The transcript derives independent client→server and server→client AES-256-GCM keys and nonce prefixes through HKDF-SHA-256.

Every encrypted frame authenticates its header as additional data and binds protocol version, type ID, session ID, persisted Velocity epoch, sequence, issue/expiry times, and logical message ID. `session + epoch + sequence` is the one-use secure-frame identity; the logical message UUID remains stable across retries. Frames are limited to 28 KiB plaintext and five minutes maximum lifetime; the normal bridge lifetime is ten seconds. A 64-sequence sliding replay window is checked only after GCM authentication.

An authenticated exact-frame replay is discarded while the session remains usable. Every legitimate retry is freshly encrypted with a new sequence and nonce, then deduplicated by logical message ID at the receiver. Authentication, session, protocol, expiry, and capability failures invalidate the network session; there is no insecure fallback. Five-minute session expiry and a one-second heartbeat/three-second peer timeout force automatic re-handshake. Session codecs, handshake key copies, and HKDF intermediates are zeroized when their lifecycle ends.

## Delivery contract

`QUEUED` and `IN_FLIGHT` are outbound logical-message states. `INBOUND_PROCESSING` reserves the receiver's idempotency identity while LunaChat dispatch is running. `DELIVERED` means that dispatch completed and causes an ACK; it never claims a client rendered the line. ACK removes the matching outbound logical identity. Session replacement resets attempt counters and frame identity, but preserves unexpired logical work.

Network channel chat is best effort at the Paper edge. LunaChat has already accepted and rendered its local message before the asynchronous bridge work is attempted. A missing carrier, Velocity restart, queue pressure, Discord outage, or ACK timeout therefore never cancels local chat or prints a generic transport failure to players. In contrast, a shared-pass mismatch or tampered frame fails closed for the bridge and is logged for operators.

## Bounds

| State | Bound / policy |
| --- | --- |
| Paper logical outbox | configurable 1–4,096 entries; max 16 KiB per message; five attempts per session; 10-second deadline |
| Velocity pending delivery | one network-global configurable 1–4,096 entry cap; fresh-frame exponential retries; logical deadline |
| Handshake challenges | 128 entries, 30-second expiry |
| Backend sessions | 512 entries |
| Logical idempotency | configurable 64–100,000 entries per backend; retain only through logical deadline + two-second replay grace; full defers new work without killing the session |
| Discord REST work | 256 in-flight requests; queue pressure drops ordinary work; shutdown performs one bounded three-second drain |
| First-login ledger | 50,000 UUIDs; append is forced to disk before notification, malformed or oversized ledgers fail closed without overwrite |

Discord user and Minecraft message content have all `@` characters neutralized for outgoing Discord relay. The only permitted role mention is the configured first-login role ID; it is generated by LunaBridge and is the only mention in that message.
